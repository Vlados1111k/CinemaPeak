# Стратегія тестування програми CinemaPeak (Lab 36)

## 1. Критичні сценарії (Core Scenarios)
* **Конфлікт замовлень (Double Booking)**: Запобігання купівлі двох квитків на одне й те саме місце або ряд.
* **Ціноутворення та Знижки**: Коректність розрахунку фінальної вартості для різних типів квитків та стратегій знижок.
* **Persistence шар**: Надійність збереження стану системи у JSON-файл та його безпомилкове відновлення при перезапуску програми.

## 2. Найважчі компоненти для тестування
* **JsonDataStore & InMemoryTicketRepository**: Компоненти виконують реальні операції введення та виведення з диском. Тестування ускладнюється потенційними блокуваннями файлів та залежністю від поточної директорії виконання.
* **Рішення**: Для юніт-тестів ці залежності ізолюються за допомогою моків (Mocks), а для інтеграційних тестів використовуються динамічні тимчасові файли через `Path.GetTempFileName()`.

## 3. Використання Mocks vs Інтеграція
* **Юніт-тести (Mocks)**: Використовуються для перевірки BookingService де репозиторій замінюється моком. Це дозволяє протестувати логіку сервісу без взаємодії з диском.
* **Інтеграційні тести (Реальна взаємодія)**: Перевіряють повний цикл взаємодії `BookingService -> InMemoryTicketRepository -> JsonDataStore -> Диск`.

## 4. Негативні сценарії
* Пошкоджений або порожній JSON-файл бази даних квитків.
* Передача від'ємних координат місць або нульової вартості квитка.
* Спроба забронювати місце, яке вже міститься в базі даних.
